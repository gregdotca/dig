- Add a test suite, block lookups against private DNS servers, add security headers, and give each lookup failure its own message.
  - **Private servers:** the Server to Query field accepted any address, so `/example.com/A/10.0.0.1` made the container query internal servers, which could reveal internal hostnames, or which internal hosts run DNS. A server is now resolved to an IP first and rejected unless every address it resolves to is public (`Error: The server to query must be a public address`). `dig` gets that IP rather than the name, so a name can't pass the check and then resolve to a private address when `dig` looks it up. Names are resolved with `dig` and the same 2-second timeout per resolver, not Python's `getaddrinfo`, which has none, so a name whose DNS never answers can't hold a worker for long. Because the name goes to `dig`, a server starting with `-` or `+` is rejected like an address (`Error: A server can't start with - or +`).
  - **Clearer messages:** an unknown record type, a server that doesn't answer, a server name that doesn't resolve, and an address with no records all showed either the generic "Error: Unable to get dig results" or nothing at all. They now say `Error: Unknown record type "XYZ". Supported types: A, NS, …`, `Error: No reply from the DNS server`, `Error: Unable to find the server "nope.invalid"`, and `No A records found for example.com`. `Error: Invalid address` is now `Error: An address can't start with - or +`, which says what's wrong.
  - **Security headers:** every response now has `X-Content-Type-Options: nosniff`, so browsers don't guess file types; `Referrer-Policy: same-origin`, so other sites don't see which addresses a visitor looked up; and `Content-Security-Policy: frame-ancestors 'none'` with `X-Frame-Options: DENY`, so other sites can't put the page in a frame for clickjacking.
  - **Tests:** there was no test suite, so nothing would have caught a regression in the security fixes. 30 pytest tests cover the redirects (including `//evil.com`), missing form fields, addresses and servers starting with `-` or `+`, private and unknown servers, resolving server names, each error message, HTML escaping of DNS records, and the headers. They replace the `dig` call and DNS resolution, so they need no network. They run in the Docker builder stage after flake8, and a failure stops the build.
  - `services/web/project/__init__.py:2-5,19-30,69-150`: imports, `DIG_EXIT_NO_REPLY`, `add_security_headers`, the new checks and messages in `run_dig`, and `resolve_public_server`.
  - `services/web/tests/test_app.py`, `services/web/pytest.ini`, and `services/web/requirements-test.txt` (pytest 9.1.1): new.
  - `services/web/Dockerfile:39-41`: install the test requirements and run pytest.
  - `CLAUDE.md`: describe the tests, the server check, the messages, and the headers.
- Fix slow or unresponsive DNS servers blocking the site, and remove jQuery and the artificial delay on lookups. gunicorn ran a single sync worker, and `dig` waits about 15 seconds by default for a server that doesn't answer, so one lookup against a dead server (such as `/example.com/A/192.0.2.1`) made every other visitor wait. gunicorn now runs 4 workers, and `dig` gets `+time=2 +tries=1`, so that lookup fails after 2 seconds while other lookups carry on (tested: about 0.015 seconds alongside it). `POST /` also slept for 0.25 seconds before redirecting, for no reason, which held a worker and slowed every lookup. jQuery (about 87 KB) was loaded only to show the loading spinner, which one line of plain JavaScript now does. A POST with missing form fields returned a 400 error; missing fields now get the defaults, as empty ones already did.
  - `services/web/project/__init__.py:3,11-14,22-29,63-67`: remove `sleep`, add `DIG_TIMEOUT_ARGS`, read the form with `.get()`, and always use a `pydig.Resolver` with the timeout options.
  - `services/web/project/templates/home.html:8,20`: remove the jQuery `<script>` tag, and show the spinner with `document.getElementById`.
  - `services/web/project/assets/jquery-3.7.1.min.js`: removed.
  - `docker-compose.yml:8`: add `--workers 4` to the gunicorn command.

- Fix the Dockerfile lint warnings and remove the unused `FLASK_ENV` setting. Docker's build checks flagged `FROM ... as builder` (lowercase `as` with uppercase `FROM`) and the legacy `ENV KEY value` format; they're now `AS builder` and `ENV KEY=value`, and `docker build --check` reports no warnings. Flask stopped reading `FLASK_ENV` in 2.3, so setting it in `docker-compose.yml` had no effect.
  - `services/web/Dockerfile:6,12-13`: `AS builder`, and `ENV KEY=value`.

- Update Python from 3.9 to 3.14, Flask from 2.3.0 to 3.1.3, gunicorn from 20.1.0 to 26.2.0, and flake8 from 7.1.2 to 7.4.1, and pin Werkzeug to 3.1.9. Python 3.9 reached end of life in October 2025, so it no longer gets security fixes. gunicorn 20.1.0 has a request-smuggling vulnerability (CVE-2024-1135, fixed in 22.0.0). Werkzeug wasn't pinned, so pip installed Werkzeug 3, which Flask 2.3.0 doesn't fully support: the site still ran, but Flask's test client crashed with `module 'werkzeug' has no attribute '__version__'`. gunicorn 26 also adds a control socket for its `gunicornc` tool, which dig doesn't use; gunicorn tried to create it in `/home/app/.gunicorn`, which the `app` user can't write to, and logged a `Permission denied` error on every start, so it's now turned off with `--no-control-socket`.

  - `services/web/Dockerfile:6,35,52`: `python:3.14.7-slim` for both stages, and flake8 7.4.1.

- Add `<!doctype html>`, `lang="en"`, and a viewport meta tag to the page, and remove three classes that did nothing. Without a doctype the browser rendered the page in quirks mode, which Tailwind's base styles don't expect; without `lang` screen readers had to guess the language; and without a viewport tag phones showed a zoomed-out desktop layout. `form` and `loading-circle` aren't daisyUI classes and `justify-left` isn't a Tailwind class (it's `justify-start`), so none of them was in the built CSS. File changed: `services/web/project/templates/home.html:1-5,15-16,24`.
- Fix an open redirect in the lookup form. `POST /` joined the typed values into a string and redirected to it, so an address of `//evil.com` sent the visitor to `//evil.com/A`, which the browser opens as another site. The redirect is now built with `url_for`, which encodes each value, so it always stays on this site. Files changed: `services/web/project/__init__.py:3,20-29`, and `CLAUDE.md`.
- Fix addresses being read as `dig` options. pydig passes the address to `dig` as its own argument without checking it, so an address starting with `-` or `+` became an option: `/-fmanage.py/A`, for example, made `dig` read `manage.py` as a list of queries, and with a server set it could send each line of the file to that server. Addresses starting with `-` or `+` now show `Error: Invalid address` without running `dig`. Files changed: `services/web/project/__init__.py:54-57`, and `CLAUDE.md`.
- Fix cross-site scripting through DNS results. The template printed `dig`'s output with `|safe`, so HTML in a DNS answer ran on the page: anyone could put a `<script>` in a TXT record on their own domain and share a `/theirdomain/TXT` link. The output is now autoescaped like every other value, which shows the text as it is. Files changed: `services/web/project/templates/home.html:28,32`, and `CLAUDE.md`.
- Add `aria-label`s to the Address, Record Type, and Server to Query inputs. They had only placeholders, so screen readers could announce them without saying what each field is for, and the hint disappeared once a value was typed or filled in from the URL. The labels match the placeholder text, so the page looks the same. File changed: `services/web/project/templates/home.html:16-18`.

- Add automatic dark mode that follows the visitor's system colour scheme, with no toggle or JavaScript. The page only had daisyUI's light `bumblebee` theme, set with `data-theme="bumblebee"` on `<html>`, so it stayed light for visitors who prefer dark. daisyUI's `business` theme is now built in as `--prefersdark`, which puts its colours inside `@media (prefers-color-scheme: dark)`; the page background, text, form, and button all switch with it. The `data-theme` attribute is removed, because daisyUI only applies the dark theme to a root without one. A `color-scheme` meta tag tells the browser about both modes before the CSS loads, which avoids a white flash. In dark mode the Lookup button uses a navy blue instead of `business`'s orange accent (`business`'s primary darkened from `oklch(41.703% .099 251.473)` to `oklch(34% .085 251.473)`, which raises the button text's contrast from 6.0:1 to 8.3:1), and the form and its fields keep `bumblebee`'s rounder corners instead of `business`'s near-square ones. Light mode keeps its black accent button and looks the same as before.
