# Changelog

## 2026-10-11

- Fix an open redirect in the lookup form. `POST /` joined the typed values into a string and redirected to it, so an address of `//evil.com` sent the visitor to `//evil.com/A`, which the browser opens as another site. The redirect is now built with `url_for`, which encodes each value, so it always stays on this site. Files changed: `services/web/project/__init__.py:3,20-29`, and `CLAUDE.md`.
- Fix addresses being read as `dig` options. pydig passes the address to `dig` as its own argument without checking it, so an address starting with `-` or `+` became an option: `/-fmanage.py/A`, for example, made `dig` read `manage.py` as a list of queries, and with a server set it could send each line of the file to that server. Addresses starting with `-` or `+` now show `Error: Invalid address` without running `dig`. Files changed: `services/web/project/__init__.py:54-57`, and `CLAUDE.md`.
- Fix cross-site scripting through DNS results. The template printed `dig`'s output with `|safe`, so HTML in a DNS answer ran on the page: anyone could put a `<script>` in a TXT record on their own domain and share a `/theirdomain/TXT` link. The output is now autoescaped like every other value, which shows the text as it is. Files changed: `services/web/project/templates/home.html:28,32`, and `CLAUDE.md`.
- Add `aria-label`s to the Address, Record Type, and Server to Query inputs. They had only placeholders, so screen readers could announce them without saying what each field is for, and the hint disappeared once a value was typed or filled in from the URL. The labels match the placeholder text, so the page looks the same. File changed: `services/web/project/templates/home.html:16-18`.
- Add an `ACR.md` file with the project's [AI Code Rating](https://aicoderating.com/spec/0.1/), B1b (Maintainer: Experienced · AI Share: 1–25% · Oversight: Reviewed), so readers can see how much of the code AI wrote and how carefully it was checked, and add its badge to `README.md`.
- Fix the README's installation step to load `http://IP_ADDRESS:8091` instead of `https://`. The container serves plain HTTP (gunicorn on port 5000, published on 8091, with no TLS), so the `https://` link failed with a TLS error.
- Add automatic dark mode that follows the visitor's system colour scheme, with no toggle or JavaScript. The page only had daisyUI's light `bumblebee` theme, set with `data-theme="bumblebee"` on `<html>`, so it stayed light for visitors who prefer dark. daisyUI's `business` theme is now built in as `--prefersdark`, which puts its colours inside `@media (prefers-color-scheme: dark)`; the page background, text, form, and button all switch with it. The `data-theme` attribute is removed, because daisyUI only applies the dark theme to a root without one. A `color-scheme` meta tag tells the browser about both modes before the CSS loads, which avoids a white flash. In dark mode the Lookup button uses a navy blue instead of `business`'s orange accent (`business`'s primary darkened from `oklch(41.703% .099 251.473)` to `oklch(34% .085 251.473)`, which raises the button text's contrast from 6.0:1 to 8.3:1), and the form and its fields keep `bumblebee`'s rounder corners instead of `business`'s near-square ones. Light mode keeps its black accent button and looks the same as before.
  - `services/web/project/styles/app.css`: add `business --prefersdark` to the daisyUI themes, and set a darker `--color-primary` and `bumblebee`'s `--radius-*` values for dark mode.
  - `services/web/project/templates/home.html`: remove `data-theme="bumblebee"`, add the `color-scheme` meta tag, and add `dark:btn-primary` to the Lookup button.
  - `CLAUDE.md`: add a dark mode note.
- Add `CLAUDE.md` with run, lint, and architecture notes for Claude Code, including how the untracked dev/prod switch scripts work.
- Update the copyright notices in `LICENSE` and `README.md` to `Copyright (c) 2025-2026 Greg Chetcuti <greg@chetcuti.com>`, so the years are current and the notices include a contact email.
- Build Tailwind 4.3.3 and daisyUI 5.7.42 CSS at Docker build time instead of loading them from jsDelivr. The page used the in-browser Tailwind compiler, a floating `daisyui@5` tag, and a separate themes file pinned to `5.0.0`, so every visitor downloaded and ran a third-party compiler, and upstream releases could change the styling without any change here. The build now produces a single minified `app.css` (about 26 KB, 5 KB gzipped) with only the classes the template uses and the `bumblebee` theme.
  - `services/web/Dockerfile`: the builder stage downloads the Tailwind standalone CLI (checksum-verified, amd64 and arm64) and builds the CSS; the final stage copies in `app.css`.
  - `services/web/project/styles/app.css`: new Tailwind input file.
  - `services/web/project/styles/daisyui-5.7.42.mjs`: vendored daisyUI plugin.
  - `services/web/project/templates/home.html`: load `app.css` locally instead of the three CDN files.
  - `.gitignore`: ignore the generated `project/assets/app.css`.
